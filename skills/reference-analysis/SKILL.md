# 参考素材分析:从灵感素材到可拍的创意

三段流水线,后一段以用户意图为闸:

```
① 取材(transcript/全文)
  → ② 批判性拆解(事实核查 + 方法论提取)   ← 用户只说"分析",到这里为止
  → ③ 创意转化(多套差异化方向 → 选定 → 进 nolan-board ②.5 出分镜)
```

## ① 取材:先拿到全文,再谈判断

- **视频/播客/短视频**:`media_transcript(url, languages=["en","zh"])`。
  **超时重试纪律(实测)**:60s 超时是常态而非故障——同参数重试,至多 3 次;
  仍失败换 URL 形态(`youtu.be/<id>` ↔ `www.youtube.com/watch?v=<id>`,去掉 `?si=` 尾巴)。
  三次形态都失败才向用户报"拿不到字幕",并给出你能做的降级(如让用户贴文字稿)。
- **文章/网页**:`web_fetch`;**用户上传的文档**:`files_read`。
- **长文本必须全量覆盖**:转写超过约 3 万字符时,把全文存进 workspace,再分块通读
  (`files_read` 分段,或有 `run_python` 时用脚本分块扫读 + 关键词定位)。
  **只读开头就下判断 = 不合格**——素材的反转和金句常在后半段。
- **工具缺位如实报**:没有 `media_transcript`/`web_search` 授权就直说缺什么、
  需要管理员在管理端给 `media`/`web` 工具组,不要凭标题和常识编内容。

## ② 批判性拆解:输出的是判断,不是摘要

产出直接写在对话里(这是给人读的分析,不是分镜正文),固定骨架:

**1. 核心判断置顶(≤3 句)。** 素材真正在讲什么(常与它的表面主张不同)、
整体可信度如何、对我们手头的产品/项目有没有用。读者只看这三句也能带走结论。

**2. 事实核查是硬步骤,不是可选项。** 素材引用的案例、数据、故事,用 `web_search`
找权威源(官方文件、一线媒体、事实核查站、原典)核验,每条标注三档之一:
**已证实(附来源链接)/ 证据不足 / 虚构**。开场地基是假的(编造的寓言、原典没有的
断言),后面"自然界/古籍/科学都证明同一件事"的权威感全部降级——明说。

**3. 方法论提取,导演四席当镜片。** 每条方法论 = **原理一句话 + 素材内的实例 +
适用边界**,不许只有形容词。用四个镜片分别读一遍:

- **Ogilvy(售卖)**:它卖的 Promise 是什么、怎么立起来的;specifics 用在哪。
- **Patel(转化)**:Hook → Value → CTA 的漏斗怎么搭;它想让观众做什么。
- **Mari(信息流)**:第一秒的停滑装置是什么;为什么手指停下来。
- **Nolan(结构/影像)**:叙事骨架(悬念怎么埋、何时释放)、节奏与情绪曲线、
  镜头/剪辑语言里可偷师的手艺。

非广告素材(纪录片、演讲、投资访谈、知识区长视频)一样拆——提取的是**它抓住并
留住注意力的手艺**,那正是效果广告要的;别因为"它不是广告"就只做内容总结。

**4. 风格红线(团队确认的验收标准)。** 分析必须尖锐、具体、可证伪:

- 每条方法论都回答"**这会改变我们怎么拍/怎么投吗?**"——不会的,归入背景知识,
  不占篇幅。
- 明确说哪条方法论**不适用**于我们的产品,以及为什么;"都可以借鉴"的平均分配式
  分析 = 不合格。
- 禁止过宽、过安全、道德化对冲的表述。有判断就下,判断错了比不判断好。

**5. 落库。** 站得住的方法论结论用 `curate_knowledge` 入库(带来源与置信度);
素材服务于某个 Studio 项目时,用 `studio_add_ref` 把素材挂进该项目。

## ③ 创意转化:多套差异化方向(用户要"出几套/出剧本"才进入)

- 出 **2–4 套差异化方向**。差异必须在骨架上——不同的 Promise、不同的叙事切角、
  不同的情绪曲线;同一骨架换场景/换人物 = 换皮,不算一套。
- 每套固定结构:
  1. **方案名 + 一句话 Promise**(Ogilvy 席审:可兑现、具体);
  2. **方法论依据**:引用 ② 里的哪几条、怎么用;
  3. **剧本骨架**:按成片时长(15s/30s)写拍——钩子(第 1 秒给什么)→ 展开 →
     payoff → CTA,逐拍一句话;
  4. **适配判断**:为什么适合该产品;或如实标注"**高风险 / 不适配**,因为…"
     ——允许某套方案的结论就是否定。
- 至少一套是你作为导演**最推荐**的,说清为什么;鼓励有一套反共识。
- 用户选定方向后:建/入 Studio 项目(`studio_project_create`,brief 里写明
  源素材与选定方法论),进 **nolan-board ②.5 线稿预览**流程细化成可生成的分镜
  验证文档——那边的全部纪律(台账唯一事实源、聊天不铺分镜长文、中断铁律、
  STYLE 从 brief 派生)照常生效,本 skill 不重复、不覆盖。

## 边界

- ② 的分析长文属于对话;**分镜正文永远只住 Studio 台账 + 导出文档**(nolan-board 铁律)。
- 分析与出方向阶段**不建任何定妆/主体**——那是用户选中方案之后 ② 定妆阶段的事。
- 多个素材对比:逐个走 ①②,最后加一段跨素材综合判断(它们互相矛盾的地方,
  正是最值得说清的判断点)。
